Kịch bản

Bối cảnh & luật chơi

  • Vai: pentester, được cấp host nexus-edge (black-box, không có source).
  • Mục tiêu: trinh sát toàn diện, thu thập các marker IAW301{...} (~17 mục).
  • Luật: thỏa sức nã tool — không rate-limit, không WAF, không ban. Bẩn thì reset một nốt.

Người trình bày: nhấn mạnh — đây là range luyện tập, không phải môi trường thật; mọi credential là giả.

Setup (một dòng)

Khởi động mục tiêu

# A. Đầy đủ (máy có Docker)
docker compose up -d --build        # 5 dịch vụ: web, api, ftp, redis, banners

# C. Không Docker (chỉ phần web) — sinh viên thiếu Docker
python serve_nodocker.py            # http://localhost:8080

Chế độ B (khuyến nghị lớp học): giáo viên host 1 instance, cả lớp chĩa tool vào host:port — không ai cần Docker.

Bước 1 · nmap

Quét cổng & dịch vụ

nmap -sV -sC -p- --min-rate 2000 <host>

Thấy nhiều dịch vụ trên nhiều cổng — không chỉ một web app:

80/8080 nginx 1.18.0 21 ftp vsftpd 2.3.4 · anon 2222 ssh OpenSSH 7.2p2 2525 smtp Postfix 6379 redis no-auth

Chốt: banner phiên bản cũ → tra CVE ngay; ftp-anon, redis mở toang.

Bước 2 · ffuf / feroxbuster

Fuzz thư mục & file

ffuf -u http://<host>:8080/FUZZ -w raft-medium-files.txt \
     -e .bak,.old,.zip,.sql,.env -mc 200,301,403 -t 100

200 — thấy ngay

/.env · /config.php.bak · /db.sql · /backup.zip · /phpinfo.php · /robots.txt · /uploads/

403 — TỒN TẠI (≠ 404)

/admin/ · endpoint có thật, chỉ bị chặn listing → đừng bỏ qua!

Chốt: lọc theo status-code (-mc/-fc/-fs) là kỹ năng cốt lõi.

Bước 2b · Source map

JS minified → lộ source gốc

Trang chủ nạp /assets/app.min.js; cuối file có //# sourceMappingURL=app.min.js.map (thấy qua View Source / tab Sources của DevTools).

curl -s http://<host>:8080/assets/app.min.js.map | jq -r '.sourcesContent[]'

sourcesContent chứa nguyên source chưa minify — lộ token build hardcode:

IAW301{source_map_leaks_original_source_and_secret}

Bài học: strip sourcemap trước khi deploy; đừng inline secret vào bundle frontend.

Bước 3 · git-dumper — điểm nhấn

/.git để hở → khôi phục source

git-dumper http://<host>:8080/.git/ ./loot
cd loot && git log --all -p | grep -i secret

Khôi phục nguyên repo. git log lộ file config.py đã bị "xoá" ở commit mới — nhưng vẫn nằm trong history:

IAW301{git_history_leaked_hardcoded_secret} DB_PASS = S3cr3t-DB-Pass-2026!

Bài học đắt: "xoá secret rồi commit lại" không xoá khỏi lịch sử git.

Bước 4 · Dịch vụ không xác thực

Redis & FTP mở toang

# Redis không mật khẩu
redis-cli -h <host> -p 6379 KEYS '*'
redis-cli -h <host> -p 6379 GET session:admin:token

# FTP anonymous
curl ftp://<host>:21/backup/credentials.txt
IAW301{unauthenticated_redis_exposed_key} IAW301{anonymous_ftp_readable_backup_credentials}
Bước 5 · Ghép chuỗi

Rò rỉ nhỏ → chiếm quyền

Từng mẩu "vô hại", ghép lại thành đường vào thật:

/db.sql
MD5 không salt → CrackStation
admin / password / 123456 → tái sử dụng mật khẩu
employee_directory.csv
danh sách email → Password Spraying → Chuyên đề Authentication
Phòng thủ

Remediation

  • Tắt banner/version (server_tokens off), autoindex, /server-status, phpinfo.
  • Chặn dotfiles & /.git ở web server; CI/CD chỉ deploy artifact sạch (không .git).
  • Gỡ .env/backup/dump khỏi web root; rotate secret đã lộ trong lịch sử git.
  • Bắt buộc xác thực Redis/FTP; cập nhật phiên bản dịch vụ.
